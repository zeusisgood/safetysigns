# 0001. 看板の図柄を、NBT に図柄 ID の文字列で持つ

- 日付: 2026-10-12
- 状態: 決定（実装は仕様書「9. 作業の順番」の 2 から。0.1.0 は図柄を w003 に固定）。0.2.0 で実装した（NBT のキーは `SignId`、TileEntity は `safetysigns:sign`。描画は [ADR 0002](0002-load-sign-definitions-on-texture-stitch.md)）

## 背景

看板の図柄は、設置後にいつでも選び直せる。最終的には ISO 7010 の全種（約 330 種）を扱い、リソースパックで図柄を追加できるようにする。
1.12.2 のブロックのメタデータは 16 通りしかなく、向き（4 方向）でもう 4 通りを使うため、図柄をメタデータやブロックの種類で持つのは無理がある。

## 決定

- 図柄はアイテムとブロック（TileEntity）の NBT に、**図柄 ID の文字列**（`<namespace>:<名前>`、64 文字まで）で持つ。番号にはしない。
- 本体の図柄は `safetysigns:` に ISO のコードを小文字で付ける（例: `safetysigns:w003`）。
- 図柄 ID は一度出したら変えない・消さない。消す・意味を変えるときはマイナーを上げる。
- サーバーは図柄の一覧を知らず、ID の文字列を保存・同期するだけ。クライアントから届いた ID は形と距離だけを確かめる。
- クライアントの一覧にない ID は「?」の図柄で表示し、ID は消さずに保持する。
- 図柄を設定していない看板は NBT を持たない（「無地」）。

## 検討した案

- **番号（整数）で持つ**: 軽いが、リソースパックで図柄が増減したり、読み込む順番が変わったりすると、既存の看板の図柄がずれる。
- **図柄ごとに別のブロック・アイテム**: 数百のブロックを登録することになり、リソースパックで追加できない。GUI で選び直すと別のブロックに置き換えることになる。
- **メタデータ**: 16 通りしかなく、向きと両立しない。

## 結果

- 図柄が増えても、ブロックとアイテムは形・サイズごとの 1 種のまま。
- 図柄違いのアイテムはスタックしない（NBT が違うため。仕様）。
- 追加パックを入れていない人には「?」と表示されるが、ID は保持されるので、パックを入れれば元の図柄に戻る。
- 前面の描画は、図柄 ID からテクスチャを引く仕組み（TileEntity の描画など）が要る。0.1.0 は固定のブロックモデルで代用している。
