# 0002. 図柄の定義ファイルを、テクスチャの貼り直しのたびに全パックから読む

- 日付: 2026-10-12
- 状態: 決定（0.2.0）

## 背景

図柄の一覧は定義ファイル（JSON）で持ち、リソースパックから追加・上書きできるようにする（仕様書 3.2）。
図柄のテクスチャは定義ファイルが指すので、テクスチャを登録する前に定義ファイルを読み終えていなければならない。
また、図柄はブロックのメタデータではなく TileEntity の NBT で持つので（[ADR 0001](0001-store-sign-pattern-as-string-id.md)）、
ブロックモデル（JSON）だけでは図柄を描き分けられない。

## 決定

- 定義ファイルは `assets/<namespace>/safetysigns/signs.json`。形は `{"signs": [ … ]}`（[`resourcepack.md`](../resourcepack.md)）。
- **ブロックのテクスチャの貼り直し（`TextureStitchEvent.Pre`）のたびに**、全名前空間の定義ファイルを `getAllResources` で読み直してマージし、同じイベントで図柄のテクスチャをブロックのテクスチャに登録する。
- **項目の ID の名前空間は、ファイルの名前空間と同じに限る**。違えば飛ばす。これで、ある ID を定義できるのは同じ名前空間のファイルだけになり、上書きの順番が `getAllResources` の返す順（パックの優先度）だけで決まる。
- `texture` はブロックのテクスチャの名前（`<namespace>:signs/<名前>`、`textures/` と `.png` を付けない）。省略したら `<namespace>:signs/<ID の名前>`。
- 看板の前面の図柄は TileEntity の描画（TESR）で、無地の板（ブロックモデル）の手前に重ねる。アイテムは、NBT に合わせてモデルを差し替える（`ItemOverrideList`）。

## 検討した案

- **独自の `IResourceManagerReloadListener` で読む**: テクスチャの登録と順番を合わせる必要があり、F3+T などで定義とテクスチャがずれるおそれがある。テクスチャの貼り直しの中で読めば、必ず同じ順に揃う。
- **ID の名前空間を自由にする**: 別の名前空間のファイルが同じ ID を定義すると、どちらが勝つかが名前空間を読む順で決まり、パックの優先度と関係がなくなる。
- **図柄をブロックモデルで描く（`IExtendedBlockState` で ID を渡す）**: チャンクの描画に乗るので軽いが、仕様書 3.4 の「夜間に看板の面だけを明るく描く」が 1.12.2 では難しい。TESR なら光の強さを面ごとに変えられる。

## 結果

- リソースパックを入れ替えるか F3+T で、定義とテクスチャがまとめて読み直される。
- TESR は既定で 64 ブロックより遠くでは描かれないので、遠くの看板は無地に見える（`doc/TODO.md`）。
- 本体の図柄を上書きしたいパックは、`assets/safetysigns/safetysigns/signs.json` に同じ ID を書く。
