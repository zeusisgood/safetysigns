# 0003. 図柄のコピーはアイテムの側で扱い、壊したときは TileEntity を残してドロップを作る

- 日付: 2026-10-12
- 状態: 決定（0.2.1。仕様書「9. 作業の順番」の 3）

## 背景

仕様書 4 では、看板アイテムを持ってスニークし、設置済みの看板を右クリックすると、図柄を手のアイテムに写す（GUI は開かず、設置もしない）。
1.12.2（Forge）は、スニーク中にどちらかの手に物があると、両手の物が `doesSneakBypassUse` を許さない限り、ブロックの `onBlockActivated` を呼ばない。
また、壊したときに図柄を保持したアイテムを落とすには、ドロップを作る時点で TileEntity の図柄を読める必要があるが、プレイヤーが壊すときはバニラがドロップより先にブロックと TileEntity を消す。

## 決定

- コピーは `ItemSafetySign.onItemUse` で扱う。スニーク中で、狙った所に看板の TileEntity があれば、図柄を写して `SUCCESS` を返す（設置しない）。書き換えはサーバーだけ。
- スニークしない右クリックは今までどおり: 看板アイテムなら `onBlockActivated` が何もせず設置、それ以外なら GUI。
- 壊したときは、`removedByPlayer` で（アイテムを落とすときだけ）ブロックを消さずに残し、`getDrops` で図柄を読み、`harvestBlock` のあとで消す（Forge で TileEntity の中身を落とすときの定番のやり方）。
- ドロップ・ピックブロック・コピーは、一覧にない ID もそのまま持ち運ぶ（ID を消さない約束）。形を確かめるのは設置するとき。

## 検討した案

- **`doesSneakBypassUse` で看板アイテムを素通りさせ、`onBlockActivated` でコピーする**: もう片方の手にほかの物があると素通りしない（両手とも許す必要がある）ため、オフの手の物しだいでコピーが設置に変わってしまう。
- **`PlayerInteractEvent.RightClickBlock` で横取りする**: 動くが、ブロックとアイテムの処理の外に分岐が増え、追いにくい。
- **`breakBlock` でアイテムを落とす**: 爆発・`/setblock` などで二重に落ちたり、クリエイティブでも落ちたりする。

## 結果

- スニーク中に看板アイテム以外の物を持って看板を右クリックすると、GUI は開かず、バニラどおりその物を使う（チェストなどと同じ慣習。仕様書 4 に注を足した）。
- 2×2・ポール付き看板では、狙ったマスから代表のマスの TileEntity をたどる処理を、コピー・ドロップ・ピックブロックの 3 か所で使うことになる。
