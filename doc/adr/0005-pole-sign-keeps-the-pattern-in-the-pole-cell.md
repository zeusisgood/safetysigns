# 0005. ポール付き看板は、最下段の支柱を代表のマスにし、図柄を最上段の板に描く

- 日付: 2026-10-12
- 状態: 決定（0.4.0。仕様書「9. 作業の順番」の 5。縦 3 ブロック・固定金具は [SPEC_2026-10-12-2.md](../spec/SPEC_2026-10-12-2.md)）

## 背景

仕様書 2 と 2.2 では、ポール付き看板は床に置き、下が支柱・最上段に 1×1 の看板で、複数ブロック方式（ADR 0004）を使う。
SPEC_2026-10-12-2 で縦 2 ブロックから 3 ブロック（下 2 段が支柱）に変え、看板とポールの間に固定金具を付けた。
ADR 0004 では「置いた所が代表のマス（左下）」としたが、ポール付きでは図柄を描くのは置いた所ではなく最上段になる。

## 決定

- 並びは `SignLayout.POLE`（幅 1・高さ 3）。ADR 0004 のとおり**置いた所（最下段の支柱）を代表のマス（部品 0）**にし、図柄の TileEntity を持たせる。中段の支柱は部品 1、最上段の板は部品 2。
- 図柄を描く面は、ブロックが決める（`BlockSafetySign.getFaceRow`・`getFaceZ`）。壁掛けは看板全体・壁に貼る板の前面、ポール付きは最上段（行 2）・支柱の手前の板の前面。`SignRenderer` と GUI のプレビュー（面の縦横比）はこれを使う。
- 見た目（北を向いたモデルで）: 支柱は 4 ピクセル角でマスの中央（x・z = 6〜10）。最上段では板の裏を通り、上端の少し下（y = 13）で止まる。板（厚さ 1 ピクセル）は z = 4〜5。板と支柱の間に、支柱を囲む固定金具（x・z = 5〜11、高さ 2 ピクセル）を y = 2〜4 と 9〜11 の 2 か所。支柱と金具はブロックモデル、板は TileEntity の描画（ADR 0006）。
- 床にだけ置く判定は、クリックした面が上面かだけを見る（`canPlaceBlockOnSide`）。下のブロックの上面が平らかは見ない。上の段のマスも同じ面で確かめる。
- 当たり判定: 支柱の段（部品 0・1）は細い柱、看板の段（部品 2）は板の外形の四角（`getBoundingBox` だけを変え、当たり判定・選んだときの枠・レイの当たりはバニラの既定でこれを使う）。看板の段の裏の支柱と金具には当たり判定がない。
- メタデータ: 下位 2 ビットが向き、上位 2 ビットが部品（0〜2。3 は使わず、読んだら 2 にする）。

## 検討した案

- **最上段（板）を代表のマスにする**: 描画は楽だが、「置いた所が代表」という ADR 0004 の決まりと 2×2 の並びの計算（代表から右・上へ）が崩れ、`SignLayout` に例外が要る。
- **支柱を板の真ん中に通す（板が支柱を挟む）**: 板の両面に支柱が出っ張り、裏も表も見た目が悪い。
- **下のブロックの上面が平らなときだけ置ける**: バニラの立て看板ほど厳しくする理由がなく、壁掛けも後ろの壁を見ていない（`doc/TODO.md`）。上の段のマスを確かめるときに下の段がまだ空気なので、判定も複雑になる。
- **看板の段の当たり判定に、裏の支柱も入れる**: 仕様（SPEC_2026-10-12-2）で、看板の段は板の外形の四角でよいとした。看板の段は人の頭より上にあり、支柱にぶつかる場面がほとんどない。

## 結果

- 下の床を壊しても、ポール付き看板は浮いたまま残る（壁掛けと同じ。`doc/TODO.md`）。
- 部品の番号は幅 1 なので、鏡に映しても変わらない（2×2 のような TileEntity のずれは起きない）。
- 上の段を置けるかの「人とぶつからないか」は、バニラが既定の状態（支柱）の当たり判定で確かめる。板の端だけに人が重なっていても置ける。
- 看板が地面から 2 ブロック上になるので、置くには 3 マスの高さが要る（天井の低い所には置けない）。
