# 0008. 夜間に光るかは看板ごとに NBT に持ち、表の図柄だけをライトマップの最大で描く

- 日付: 2026-10-12
- 状態: 決定（0.6.0。[SPEC_2026-10-12-4.md](../spec/SPEC_2026-10-12-4.md)）

## 背景

MVP の仕様書（3.4・7）では、看板の面を明るさ最大で描くかを、クライアントの全体設定 `fullbright`（既定 ON）で切り替える予定だった。
SPEC_2026-10-12-4 で、これを看板ごとの設定に変える。光るのは表面（図柄）だけで、周りは照らさず、下地・裏・縁・ポール・金具は周りの明るさのまま。

## 決定

- 光るか（`glow`）を `common/SignAppearance` に足す（図柄 ID・切り抜き・裏面と同じく、TileEntity・アイテム・通信・GUI で持ち運ぶ。[ADR 0007](0007-keep-cutout-and-back-face-per-sign.md)）。
- NBT は `Glow`。光らないときだけ `false` を書き、キーなしは光る（初期値 ON）。
  - 無地の看板も表が光るので、切り抜きと違い、無地でも OFF を持てる（ON にそろえない）。
- `MessageSetSign` は、裏面のあとに光るかの真偽値を送る。
- 描き方（`SignRenderer`）:
  - ディスプレイリストを 2 つ続きで作る。1 つ目が下地・裏・縁、2 つ目が表の図柄。
  - 1 つ目を周りの明るさ（板のあるマスの `getCombinedLight`）で描き、光る看板では、ライトマップを最大（240, 240）にしてから 2 つ目を描く。描き終わったら周りの明るさに戻す。
  - 表の図柄は 1 つ目の下地のあとに描くので、同じ位置の下地より上に出る（深さの比べ方が「以下」のため。0.5.0 と同じ順番）。図柄の透明な所はアルファテストで描かれないので、その下の下地は周りの明るさのまま見える。
  - 光るかはリストの中身を変えないので、リストのキーには足さない。
- `@Config` の全体設定（`fullbright`）は作らない。

## 検討した案

- **クライアントの全体設定 `fullbright`（MVP の案）**: 通信が変わらない。ただし看板ごとには選べず、見る人によって見た目が違う。ユーザーの要望（看板ごとに GUI で切り替え、全員に同期）に合わない。
- **光源ブロックにする（`getLightValue`）**: 周りまで照らしてしまう。仕様（周りは照らさない）に合わない。
- **ライトマップを無効にして描く（`disableLightmap`）**: 同じく最大の明るさになるが、テクスチャユニットの切り替えが増え、シェーダーの Mod との相性も読みにくい。ライトマップの座標を変えるだけのほうが、バニラの光る描画（エンダーマンの目など）に近い。
- **1 つのリストの中でライトマップの座標を変える**: `OpenGlHelper` はライトマップの座標を Java の側にも覚えるので、リストに記録すると覚えている値と GL の値がずれる。リストを分けた。

## 結果

- 通信内容が変わるので、0.6.0 にし、0.5.x とは接続できない。0.5.x のワールドはそのまま読める。
- キーがない既存の看板とアイテムは、0.6.0 から表が光る（MVP の `fullbright` の既定 ON と同じ見た目）。
- 光らないアイテムはキーを 1 つ持つので、既定のアイテムとはスタックしない（切り抜き OFF と同じ扱い）。
- ディスプレイリストの数は 0.5.0 の 2 倍になる（中身は同じ量）。
