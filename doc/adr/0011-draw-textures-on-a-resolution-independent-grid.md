# 0011. 図柄は解像度によらない設計の座標で書き、出力のマス目に直接ドット絵として塗る

- 日付: 2026-10-12
- 状態: 決定（1.0.1。[SPEC_2026-10-12-6.md](../spec/SPEC_2026-10-12-6.md)）。既定の解像度は 1.0.3 で 128 にした（[ADR 0014](0014-draw-all-builtin-pictograms-at-128.md)）

## 背景

MVP の図柄は 32×32 で、記号は「#」で書いたドット絵だった。ISO 7010 の図柄（人物・保護具・矢印など）を増やすには 32 では細部が描けないので、64×64 に上げる。
「#」のドット絵は解像度ごとに描き直しになるうえ、人物の姿勢や矢印の向きのように、同じ部品を少しずつ変えて使い回すのが難しい。
一方で、ドット絵としての見た目（中間色なし・にじみなし・切り抜きの形がはっきりしている）は保ちたい。

## 決定

- 部品は、点が内側かを答える関数（`raster.Shape`）として、解像度によらない**設計の単位**（キャンバス全体が 0〜64）で書く。円・太線・多角形などを足す・抜く・重ねるで組む。
- 塗るときは、出力の解像度のピクセルごとに、ピクセルの中心が図形の内側かだけで決める。アンチエイリアスはせず、大きく描いてから縮めることもしない。
- 解像度は `generate.py --size` で選ぶ（16〜512 の 2 の累乗、既定 64）。本体は 64 でコミットし、図案も 64 で見て決める（注: 1.0.3 で既定は 128 になり、本体は 128 でコミットし、図案も 128 で見て決める。ADR 0014）。
- 人物は関節の位置（骨組み）を決め、頭は円・胴と手足は太線でつなぐ。姿勢は骨組みを変えるだけで作る。重なった手足の境目は、手前の部品の周りを細く抜いて見せる（`raster.layered`）。
- 記号が地の縁に近すぎないかを、解像度によらない細かいマス目で確かめ、近すぎたら止まる（解像度を変えても結果が変わらないように）。
- 手で仕上げる仕組み（`manual/`、[ADR 0009](0009-generate-textures-from-parts-with-manual-overrides.md)）は残すが、本体の図柄では使わない。

## ほかの案

- **「#」のドット絵を 64 で描き直す**: 一番手軽だが、解像度を変えるたびに全部描き直しで、人物の姿勢・矢印の向きなどの変化を部品として持てない。
- **大きく（例: 512）描いてから 64 に縮める**: 縮めると中間色とにじみが出て、切り抜きの形（アルファ）も曖昧になる。色を減らして戻すと、細い線が切れたりつぶれたりして、形が崩れる。
- **ベクターの画像（SVG）を元にする**: 既存の SVG を取り込む・なぞるのは、図案を自分で描くという方針に反する。自分で SVG を描いても、ラスタライズで上と同じ問題が出る。

## 影響

- 図柄を足す手順と部品の一覧は `doc/development.md`、部品の一覧画像は `doc/textures/parts.png`、流れの図は `doc/diagrams/texture-generation.md`。
- 描画（ブロック・アイテム・GUI）はもともとテクスチャの解像度に依存しない（板の形はテクスチャの幅・高さに対する割合で作る、アイテムは層ごとにテクスチャの大きさで作る、GUI はテクスチャの地図の座標で貼る）ので、解像度の違う図柄が混ざっても描ける。リソースパックの図柄は 2 の累乗の正方形なら解像度を問わない（`doc/resourcepack.md`）。
- 図案は 64 で決めているので、32 以下で出すと細い所がつぶれる。解像度を変えてコミットするときは、図案も見直す。
