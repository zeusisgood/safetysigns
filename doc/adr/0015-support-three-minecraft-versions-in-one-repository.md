# 0015. 1 つのリポジトリに Minecraft の版ごとのビルドを置く

- 日付: 2026-10-25
- 状態: 決定（[SPEC_2026-10-25-2.md](../spec/SPEC_2026-10-25-2.md)）

## 背景

weakspot（`zeusisgood/weakspot`）と同じ 3 つの Minecraft の版（1.12.2 + Forge・1.20.1 + Forge・1.21.1 + NeoForge）に対応する。
版ごとに、ローダーの API・ビルドの道具（ForgeGradle 3 / 6、ModDevGradle）・JDK（8 / 17 / 21）・Gradle の版が違う。
一方で、図柄のテクスチャ・定義ファイル・翻訳・Minecraft に依存しない計算は、どの版でも同じ。

## 決定

- 1 つのリポジトリに、版ごとのディレクトリ（`mc1.12.2/` など）を置く。それぞれ別々の Gradle のビルドにする。
- 版に依存しないものは直下に置き、各版のビルドがソースとして読む: `common/`（計算とテスト）・`lang/`（翻訳の正本。json）・`shared/`（テクスチャ・`signs.json`・ロゴ）。
- テクスチャのディレクトリは 1.13 以降の慣習の `block`・`item` にする（1.20 以降のブロックの atlas に、何も書かずに入る）。
- 1.20.1・1.21.1 では、図柄のテクスチャを atlas の `directory` のソース（`signs/`）で集める。リソースパックの図柄は `textures/signs/` の下だけが使える。
- CI は版ごとの matrix のジョブと、全部が通ったときだけ成功する `build`。Release は全部の版の jar を 1 つにまとめる。

## ほかの案

- **版ごとにブランチを分ける**: 今の形を崩さないが、修正を何本ものブランチに手で移すことになり、ずれやすい。
- **1 つのマルチプロジェクト / Architectury**: 共通のコードは増えるが、ForgeGradle 3（Gradle 4.9）と新しい道具が同じ Gradle で動かず、Architectury は 1.12.2 に対応しない。
- **atlas に 1 枚ずつ（`single`）書く**: テクスチャのディレクトリ名を変えずに済むが、テクスチャを足すたびに json も直す必要があり、忘れると「テクスチャなし」になる。

## 影響

- 版の番号を書く場所が版の数だけ増える（`ReleaseFilesTest` で揃い具合を確かめる）。
- 1.12.2 でも、本体のブロック・アイテムのテクスチャのパスが変わった（`blocks/` → `block/`、`items/` → `item/`）。それらを差し替えるリソースパックは効かなくなる（文書に載せていない使い方）。図柄のテクスチャ（`signs/`）と図柄 ID は変わらない。
- 機能を足す・直すときは、全部の版を同じ PR で直す。
