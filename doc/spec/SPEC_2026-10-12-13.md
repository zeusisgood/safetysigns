# Safety Signs 仕様書（2026-10-12・その 13）: 図柄を書き換えられる人を絞る（アドベンチャーモード・土地保護 Mod）

図柄を書き換えられる人を絞る。いまは観戦者とスポーン保護の内側だけを弾いていて、アドベンチャーモードの人も、土地保護 Mod が守る場所の看板も書き換えられる。
ここに書いていないことは、それまでの仕様書と現行の実装のまま。

同じ日に 13 個目の仕様書なので、ファイル名の日付のあとに `-13` を付けた。

## 1. 変えること

MVP の「マルチでは誰でも図柄を変えられる」（[MVP](SPEC_2026-10-12.md) の 4）を、次のように絞る。ロック機能（看板ごとに持ち主を決める）は今までどおり後回し。

| 場面 | 今 | 変えたあと |
|---|---|---|
| アドベンチャーモード | GUI が開き、書き換えられる | **GUI を開かない**（右クリックしても何も起きない）。届いた通信も断る |
| 土地保護 Mod が右クリックを止めた場所 | GUI が開き（クライアントだけで開くため）、書き換えられる | GUI は開くことがある（保護 Mod がサーバーにだけ入っているとき）が、**書き換えは断る**（看板は変わらない） |
| 観戦者・スポーン保護の内側・8 ブロックより遠い | 断る | 断る（今までどおり） |

- アドベンチャーモードかどうかは、バニラの「ブロックをいじってよいか」（`EntityPlayer.isAllowEdit()`）で見る。クライアントは自分のモードを知っているので、GUI を開く前に確かめられる。
- 断ったときに、チャットなどへの知らせは出さない。

## 2. 土地保護 Mod への対策: 開いてよい看板をサーバーが覚える

土地保護 Mod（FTB Utilities のクレームなど）は、サーバーで右クリック（Forge の `RightClickBlock`）を止めて守る。止められると、サーバー側の `onBlockActivated` は呼ばれない。これを使う。

1. サーバー側の `BlockSafetySign.onBlockActivated` が GUI を開く条件（メインの手・看板アイテムを持っていない・ブロックをいじってよい）を満たしたら、**そのプレイヤーが開いてよい看板**として、ディメンションと代表のマスの位置を 1 つ覚える（前に覚えた看板は忘れる）。
2. `MessageSetSign` は、今までの確かめ（ID の形・読み込み済み・8 ブロック以内・観戦者でない・スポーン保護）に加えて、**ブロックをいじってよいか**と、**届いた位置が覚えた看板と同じか**を確かめる。違えば何もしない。
3. 覚えた看板は、ログアウトで忘れる。メモリに持つだけで、保存はしない（サーバーを止めれば消える）。

- サーバーで右クリックをもう一度起こして確かめる（`ForgeHooks.onRightClickBlock` を呼ぶ）方法はとらない。GUI を触るたびに偽の右クリックが起き、保護 Mod のチャットの警告や、手の物で動く他の Mod の処理が余計に走るため。
- 通信の中身・保存データ・設定は変えない。

## 3. 片付け

- 使われていない `SignTextures.sprite(String)` を消す。

## 4. 文書

- `doc/architecture.md` の「図柄を変える流れ」と図、`doc/diagrams/right-click.md` の分岐（アドベンチャーモードでは GUI を開かない）を直す。

## 5. 版

- 通信内容・保存データ・図柄 ID・設定キーを変えないので、パッチで `1.0.5` にする（1.0.x 同士で接続できる）。
- 1.0.4 以前のクライアントでも、断る判定はサーバーでするので効く（アドベンチャーモードで GUI が開くだけ）。
