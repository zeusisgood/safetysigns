# Safety Signs 仕様書（2026-10-12・その 4）: 夜間に光る設定を看板ごとに持つ

[MVP の仕様書](SPEC_2026-10-12.md)の「3.4 夜間の描画」と「7. 設定」を、この仕様書で置き換える（MVP の作業 6）。
MVP では、看板の面を光らせるかをクライアント全体の設定 `fullbright` で切り替える予定だった。これをやめ、[その 3](SPEC_2026-10-12-3.md) の切り抜き・裏面と同じく**看板 1 枚ごとの設定**にする。
ここに書いていないことは、それまでの仕様書と現行の実装のまま。

同じ日に 4 つ目の仕様書なので、ファイル名の日付のあとに `-4` を付けた。

## 1. 夜間に光る

| 項目 | 内容 |
|---|---|
| 光る所 | 看板の**表面（図柄の面）だけ**。明るさ最大で描く |
| 周り | 照らさない（光源ブロックにはしない） |
| 光らない所 | 切り抜きの透明な部分（切り抜き OFF のときに図柄の透明な所から見える下地 `#E4E6E8` を含む）、裏面（裏面 図柄のときも）、縁、ポール、固定金具。これらは周りの明るさのまま |
| 対象 | 壁掛け 1×1・2×2・ポール付きのすべて |
| 持つ場所 | **看板 1 枚ごと**。看板（TileEntity）とアイテムの NBT に持つ。複数ブロックの看板は、図柄と同じく代表のマスが持つ |
| 初期値 | **ON**。NBT にキーがなければ ON |

- 無地の看板も、表の面（無地のテクスチャ）が光る。切り抜きと違い、無地でも ON/OFF を持つ。
- 一覧にない ID（「?」）の看板は、ON/OFF の値をそのまま保持する（「?」の図柄が光る）。

## 2. GUI

- 右のプレビューの**下**に、切り替えボタン「**夜間に光る: ON / OFF**」を置く。押すたびに切り替わる。
- 図柄と同じく**押したら即反映**（決定ボタンなし）。押すたびにサーバーへ送り、サーバーから全員に同期する。
- 無地の看板でも押せる。
- ボタンの文字は `en_us.lang`（`Night glow: ON / OFF`）と `ja_jp.lang` の両方に足す。
- コードと名前の表示は、ボタンの下に下げる。

## 3. アイテム・操作

- アイテムのアイコンには出さない。ツールチップに、OFF のときだけ「光らない」を 1 行足す（切り抜き・裏面と同じく、既定と違う設定だけを出す）。
- 設置するとき、アイテムの ON/OFF を看板に引き継ぐ。
- スニーク右クリックでのコピー、ピックブロック、壊したときのドロップで、図柄と一緒に ON/OFF も写す。
- 看板アイテム 1 個だけのクラフト（無地に戻す）では、光る設定も初期値（ON）に戻る（NBT なしになる）。

## 4. サーバー

- クライアントから届く値も、図柄と同じく、看板が届く距離にあるか・いじってよい場所かを確かめてから書き込む（真偽値なので形の確認は要らない）。

## 5. 設定

- クライアントの全体設定（`fullbright`）は**作らない**。この版では `@Config` の項目はない（`config/safetysigns.cfg` も作らない）。

## 6. バージョン

- サーバーへ送る中身（通信内容）に光る設定が増えるため、互換性を破る。**0.6.0** にし、`acceptableRemoteVersions` を `[0.6,0.7)` にする。`CHANGELOG.md` に 0.5.x とは接続できないことを書く。
- NBT のキーを足すだけなので、0.5.x で作ったワールドはそのまま読める。キーがない＝ ON なので、**既存の看板とアイテムは、この版から表面が光る**（MVP の `fullbright` の既定 ON と同じ見た目）。
