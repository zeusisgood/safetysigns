# Safety Signs 仕様書（2026-10-25-2）: 1.20.1 + Forge・1.21.1 + NeoForge に対応する

weakspot（`zeusisgood/weakspot`）と同じ 3 つの Minecraft の版に対応する。

| Minecraft | ローダー | 開発に使う版 | 備考 |
|---|---|---|---|
| 1.12.2 | Forge | 14.23.5.2860 | 古い Forge では一部の機能が動かない可能性あり |
| 1.20.1 | Forge（47.1.32 以降） | 47.1.32 | |
| 1.21.1 | NeoForge | 21.1.264 | |

ここに書いていないことは、それまでの仕様書と現行の実装のまま。機能・見た目・操作は 3 つの版で揃える（新しい版でも、1.12.2 版と同じ看板・図柄・GUI・レシピにする）。

## 0. 相談で決めたこと

1. リポジトリの形は weakspot と同じにする（1 つのリポジトリに版ごとのディレクトリ。ブランチで分けない）。
2. 公開の順番: 1.12.2 版は今の 1.0.x を先に公開し、新しい版はあとから足す。
3. 版の番号: 3 つの jar をいつも同じ番号で出す。新しい版を足すときは**マイナー**を上げる（→ `1.1.0`）。
4. 新しい版（1.20.1・1.21.1）では、リソースパックの図柄テクスチャを `textures/signs/` の下だけにする（1.12.2 版は今のまま）。
5. PR は 2 本に分ける: (1) リポジトリの形だけを変える、(2) 1.20.1 と 1.21.1 の移植をまとめて 1 本。

## 1. リポジトリの形（PR 1）

### 1.1 ディレクトリ

```
common/          版に依存しない計算（Minecraft のクラスを持ち込まない。Java 8 の書き方）とそのテスト
lang/            翻訳の正本（en_us.json・ja_jp.json）
shared/          全部の版で同じリソース（下の 1.2）
mc1.12.2/        1.12.2 + Forge のビルド（今の build.gradle・src・gradlew などをここへ移す）
mc1.20.1/        1.20.1 + Forge のビルド（PR 2）
mc1.21.1/        1.21.1 + NeoForge のビルド（PR 2）
doc/ tools/ CHANGELOG.md README*.md LICENSE   直下で全部の版に共通
```

- それぞれ別々の Gradle のビルドにする（1 つのマルチプロジェクトにはしない。weakspot と同じ理由: ForgeGradle 3・ForgeGradle 6・NeoForge の ModDevGradle が同じ Gradle で動かない）。
- 各版の `build.gradle` が `../common/src/main/java`・`../common/src/test/java`・`../shared` をソースとして読む。
- テストの作業ディレクトリはリポジトリの直下（`test { workingDir = file('..') }`）。`common/` のテストはどの版のビルドでも流れる。
- 版のファイルの揃い具合を見る `ReleaseFilesTest` は、MC に依存しないので `common/src/test/java/.../resources/` に移す。

### 1.2 共通のリソース（`shared/`）

| 置く物 | パス |
|---|---|
| 図柄・ブロック・アイテムのテクスチャ | `shared/assets/safetysigns/textures/{signs,block,item}/` |
| 図柄の定義ファイル | `shared/assets/safetysigns/safetysigns/signs.json` |
| Mod のロゴ | `shared/logo.png` |

- テクスチャのディレクトリ `blocks`・`items` を、1.13 以降の慣習に合わせて `block`・`item` に改名する（1.20 以降の atlas にそのまま入るようにするため。下の 3.2）。1.12.2 版のモデルの json はパスだけ直す。図柄の ID・テクスチャ名（`<namespace>:signs/<名前>`）は変えない。
- ブロックの状態・モデル・レシピ・`mcmod.info`／`mods.toml` は版ごとに形が違うので、各版の `src/main/resources` に置く。
- `tools/texgen/generate.py` の出力先を `shared/` に変える（`doc/` の一覧画像・アイコンはそのまま）。

### 1.3 翻訳

- 正本は `lang/en_us.json`・`lang/ja_jp.json`（1 行に 1 つの `"キー": "値"`）。キーは 1.13 以降の形にする（ブロックの名前は `block.safetysigns.<名前>`）。
- 1.12.2 版は、ビルドのときに json から `.lang` を作る（`block.safetysigns.<名前>` は `tile.safetysigns.<名前>.name` にする。ほかのキーはそのまま）。1.20.1・1.21.1 版は json をそのまま jar に入れる。
- 日英のキーが一致すること・同じキーが 2 回ないことは、テスト（`LangFilesTest`、`common/` 側）で確かめる。

### 1.4 CI とリリース

- `.github/workflows/ci.yml` を weakspot と同じ形にする: Minecraft の版ごとの matrix のジョブ（`build (<版>)`）と、全部が通ったときだけ成功する `build`（ブランチの保護に要るチェックの名前は `build` のまま）。PR 1 の matrix は 1.12.2 だけ。
- タグと GitHub Release は、`ci.yml` の `release` ジョブが `build` のあとで作る（全部の版の jar を付ける）。`release.yml` は消す。タグがすでにあれば何もしない、CHANGELOG の節がなければ失敗する、という今の動きは残す。
- CurseForge への自動の公開は入れない（weakspot にはあるが、今回は範囲の外）。

### 1.5 PR 1 の版

- 動き・jar の中身は変えないので、版は `1.0.5` のまま（タグ `v1.0.5` があるので Release は作られない）。
- 版を揃える場所は `mc1.12.2/build.gradle` の `version` と `SafetySignsMod.VERSION` に変わる。`CLAUDE.md`・`doc/development.md`・`doc/architecture.md`・`doc/diagrams/release.md`・`doc/diagrams/texture-generation.md` のパスと手順を直す。

## 2. 1.20.1 と 1.21.1 への移植（PR 2）

### 2.1 ビルド

| | 1.20.1 | 1.21.1 |
|---|---|---|
| ディレクトリ | `mc1.20.1/` | `mc1.21.1/` |
| JDK | 17 | 21 |
| Gradle・プラグイン | weakspot の `mc1.20.1/` と同じ（ForgeGradle 6、Gradle 8.8） | weakspot の `mc1.21.1/` と同じ（ModDevGradle、Gradle 8.14.3） |
| 対応するローダー | Forge 47.1.32 以降（`mods.toml` の下限も 47.1.32） | NeoForge 21.1.264 以降 |
| マッピング | official（Mojang の名前） | official |
| 版の場所 | `mc1.20.1/gradle.properties` の `mod_version`、1.20.1 の `SafetySignsMod.VERSION` | `mc1.21.1/gradle.properties` の `mod_version`、1.21.1 の `SafetySignsMod.VERSION` |
| メタデータ | `META-INF/mods.toml` | `META-INF/neoforge.mods.toml` |

- パッケージは 3 つの版とも `io.github.zeusisgood.safetysigns`。
- 版のある場所は合わせて 6 か所。`ReleaseFilesTest` で全部が揃っていること・`CHANGELOG.md` の一番上の見出しと同じことを確かめる。

### 2.2 置き換える仕組み

| 部分 | 1.12.2 | 1.20.1 | 1.21.1 |
|---|---|---|---|
| 登録 | `RegistryEvent` | `DeferredRegister` | `DeferredRegister` |
| ブロックの向き | メタデータ | `BlockState` のプロパティ | 同左 |
| 看板の板の描画 | TESR | `BlockEntityRenderer` | 同左 |
| 図柄を持つアイテムのアイコン | `SignItemModel` | `BakedModel` のラッパー（ItemOverrides） | 同左 |
| アイテムが持つ図柄 | NBT（`SignId`・`Cutout`・`BackPattern`・`Glow`） | NBT（同じキー） | データコンポーネント `safetysigns:sign_appearance`（4 つの値を 1 つの record に。既定値は書かない） |
| 看板（ブロック）が持つ図柄 | NBT | NBT（同じキー） | NBT（同じキー） |
| 図柄 GUI | `GuiScreen` | `Screen` + `GuiGraphics` | 同左 |
| GUI を開く | `IGuiHandler` | クライアントで直接開く（下の 2.4） | 同左 |
| 通信 | `SimpleNetworkWrapper` | `SimpleChannel` | `CustomPacketPayload` + `StreamCodec` |
| レシピ | `assets/…/recipes/`、`RecipeClearSign` | `data/safetysigns/recipes/`、`CustomRecipe` | `data/safetysigns/recipe/`、`CustomRecipe`（`CraftingInput`） |
| 鉄の材料 | 鉱石辞書 `ingotIron`・`plateIron` | タグ `forge:ingots/iron`（板のタグは使わない） | タグ `c:ingots/iron` |
| クリエイティブタブ | 今と同じ | `CreativeModeTab` を登録 | 同左 |
| 版の照合 | `acceptableRemoteVersions` | 通信のプロトコルの文字列（マイナーの番号 `1.1`） | 同左 |

- 1.12.2 版のレシピの「鉄板（`plateIron`）でも作れる」は、1.20.1・1.21.1 には揃った板のタグがないので鉄インゴットだけにする。
- 構造（複数ブロック・代表の 1 マス・アイテムは 1 個だけ落とす・届く距離の確かめ・図柄 ID の形の確かめ・一覧にない ID は「?」で持ち続ける）は 3 つの版で同じ。版に依存しない部分は `common/` を使い、新しく書く計算も `common/` に置く。
- 1.12.2 版にない不具合の直し・機能は足さない（移植だけ）。

### 2.3 図柄テクスチャの読み込み（1.20.1・1.21.1）

1.19.3 以降は `TextureStitchEvent.Pre` でテクスチャを足せないので、ブロックの atlas に足す形にする。

- `shared/` ではなく各版の `src/main/resources/assets/minecraft/atlases/blocks.json` に、`directory` のソースを 1 つ足す（`"source": "signs", "prefix": "signs/"`）。これで、全部のパック・全部の namespace の `textures/signs/` の下が atlas に入る。
- ブロック・アイテムのテクスチャ（`textures/block`・`textures/item`）は、Minecraft がもともと持っているソースで入る。
- 定義ファイル（`<namespace>:safetysigns/signs.json`）は、今までと同じく全部のパックをマージして読む。読むのは、リソースの再読み込みのとき（`RegisterClientReloadListenersEvent` に登録した読み込み）。
- 定義ファイルの `texture` が `signs/` の下でないとき、1.20.1・1.21.1 では「?」の図柄で出し、ログに 1 回だけ警告を出す（1.12.2 版は今のまま、どのパスでも使える）。
- リソースパックの `pack.mcmeta` の `pack_format` は版ごとに違う（1.20.1 は 15、1.21.1 は 34）。`doc/resourcepack.md` に、版ごとの `pack_format` と、新しい版では `textures/signs/` の下だけが使えることを書く。

### 2.4 GUI を開く

- 1.12.2 版と同じく、看板を右クリックしたら図柄を選ぶ画面が開く。新しい版にはモジュール間の GUI ハンドラーがないので、クライアント側で右クリックを受けたとき（`useWithoutItem` などのクライアントの側）に、クライアントのクラスを通して画面を開く。専用サーバーでクライアントのクラスに触らないようにする（weakspot の proxy と同じ考え方）。
- 図柄を決めたときの通信（図柄 ID・切り抜き・裏面・夜間の明るさ）は、1.12.2 版と同じ中身にする。サーバー側の確かめも同じ。

### 2.5 jar の名前

weakspot に合わせて、jar の名前にローダーを入れる。

| 版 | jar |
|---|---|
| 1.12.2 | `safetysigns-1.12.2-forge-<版>.jar`（1.0.5 までは `safetysigns-1.12.2-<版>.jar`） |
| 1.20.1 | `safetysigns-1.20.1-forge-<版>.jar` |
| 1.21.1 | `safetysigns-1.21.1-neoforge-<版>.jar` |

- CI の matrix に 1.20.1（JDK 17）・1.21.1（JDK 21）を足す。Release には 3 つの jar を付ける。

## 3. 版（PR 2）

- 新しい版を足すので、マイナーを上げて **`1.1.0`** にする（相談で決めたこと）。6 か所を揃える。
- 1.12.2 版の `ACCEPTED_VERSIONS` を `[1.1,1.2)` にする。1.20.1・1.21.1 版のプロトコルの文字列は `1.1`。
- `CHANGELOG.md` の `1.1.0` に、1.20.1 + Forge・1.21.1 + NeoForge に対応したこと、jar の名前が変わったこと、**1.12.2 版でも 1.0.x とは接続できない**こと（サーバーとクライアントを両方 1.1.0 にする）を書く。
- 1.12.2 版の中身は、レシピ・図柄・保存データとも 1.0.5 と同じ（既存のワールドはそのまま読める）。

## 4. 文書

- `README.md`・`README.en.md` に「対応する版」の表（Minecraft・ローダー・開発に使う版・備考。この仕様書の冒頭の表と同じ）を足す。
- `CLAUDE.md`: プロジェクト概要の対象の版、開発環境・コマンド（版ごとの JDK とビルドのしかた、jar の場所）、バージョンの 6 か所、「機能を足す・直すときは、3 つの版で同じ PR で行う」、`lang/` の json。
- `doc/architecture.md` と全体構成の図に、`common/`・`shared/`・`lang/` と 3 つの版の関係、版ごとに違う所（上の 2.2 の表）を足す。図柄の読み込みの図（`doc/diagrams/sign-definitions.md`）に、新しい版の atlas の流れを足す。
- `doc/development.md`: 版ごとのビルド、クラウドでの JDK の入れ方とネットワークの許可（`maven.minecraftforge.net`・`maven.neoforged.net`・`piston-meta.mojang.com`・`piston-data.mojang.com`・`libraries.minecraft.net`・`resources.download.minecraft.net`）、リリースの手順。
- `doc/store/description.md` に対応する版を書く。
- ADR を 1 本足す: `doc/adr/0015-support-three-minecraft-versions-in-one-repository.md`（1 つのリポジトリに版ごとのビルド、`shared/`、atlas の `signs/` の制限）。

## 5. 止まる条件（この仕様書に固有のもの）

- 新しい版で、図柄の切り抜きの形（`SignOutline`）や夜間の明るさを、1.12.2 版と同じ見た目で描く方法が見つからない。
- 新しい版で、右クリックで GUI を開く・通信で図柄を決める流れが、サーバーの確かめを残したまま作れない。
- 環境のせいで 1.20.1・1.21.1 をビルドできない（ネットワークの拒否など）。このときは push と PR をせず、拒否されたホストと直し方を報告する。

## 6. 試してほしいこと

- 3 つの版それぞれで（シングルと testserver のマルチ）: 3 種の看板を置ける・壊すとアイテムが 1 個落ちる、2×2・ポール付きの 1 マスを壊すと全体が消える。
- 図柄を選ぶ画面（検索・タブ・切り抜き・裏面・夜間の明るさ）が 1.12.2 版と同じように使え、すぐに看板に出る。
- 切り抜きの形・裏面・夜間に光る見た目が、1.12.2 版と同じに見える。
- 図柄を持つアイテムのアイコン、看板を壊して拾ったアイテムをもう一度置いたときに図柄が残る。
- レシピ（3 種と、図柄を消すレシピ）。
- 本体の図柄を足したリソースパック（`doc/resourcepack.md` の例）が、1.20.1・1.21.1 でも使える。
- 1.12.2 の 1.1.0 で、既存のワールドの看板がそのまま出る。
